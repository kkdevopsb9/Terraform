# Terraform `for_each` Meta-Argument

## 1. What is `for_each`?

`for_each` is a Terraform **meta-argument** used to create multiple instances of a resource or module from a **map** or a **set of strings**.

Unlike `count`, which identifies resources using numeric indexes:

```text
[0]
[1]
[2]
```

`for_each` identifies resources using meaningful **keys**:

```text
["dev"]
["test"]
["prod"]
```

---

# 2. Basic Syntax

```hcl
resource "resource_type" "resource_name" {

  for_each = collection

  # Resource configuration
}
```

Inside the resource, Terraform provides:

```hcl
each.key
each.value
```

### Meaning

```text
each.key   → Current key
each.value → Current value
```

---

# 3. Simple Example Using a Set

Suppose we need three IAM users:

```text
dev
test
prod
```

We can use:

```hcl
resource "aws_iam_user" "users" {

  for_each = toset([
    "dev",
    "test",
    "prod"
  ])

  name = each.value
}
```

Terraform creates:

```text
aws_iam_user.users["dev"]
aws_iam_user.users["test"]
aws_iam_user.users["prod"]
```

The actual IAM users will be:

```text
dev
test
prod
```

---

# 4. What is `toset()`?

`for_each` can directly work with a **set of strings** or a **map**.

If we have a list:

```hcl
[
  "dev",
  "test",
  "prod"
]
```

we can convert it into a set:

```hcl
toset([
  "dev",
  "test",
  "prod"
])
```

Then use:

```hcl
for_each = toset([
  "dev",
  "test",
  "prod"
])
```

---

# 5. `each.key` and `each.value` with a Set

For:

```hcl
for_each = toset([
  "dev",
  "test",
  "prod"
])
```

With a set of strings, the key and value are the same:

```text
each.key     each.value

dev          dev
test         test
prod         prod
```

So either can identify the current string, though `each.value` is often clearer when thinking of the set's item.

# Use Case 1: Create Multiple IAM Users

```hcl
provider "aws" {
  region  = "ap-south-1"
  profile = "terraform"
}


resource "aws_iam_user" "users" {

  for_each = toset([
    "developer1",
    "developer2",
    "developer3"
  ])

  name = each.value

  tags = {
    Environment = "Dev"
  }
}
```

Terraform creates:

```text
developer1
developer2
developer3
```

Resource addresses:

```text
aws_iam_user.users["developer1"]
aws_iam_user.users["developer2"]
aws_iam_user.users["developer3"]
```

---

# Use Case 2: IAM Users Using a Variable

Instead of hardcoding users inside the resource:

```hcl
variable "iam_users" {

  type = set(string)

  default = [
    "dev",
    "test",
    "prod"
  ]
}


resource "aws_iam_user" "users" {

  for_each = var.iam_users

  name = each.value
}
```

Result:

```text
dev
test
prod
```

---

# Use Case 3: Create Multiple EC2 Instances

We can do the same with EC2.

```hcl
provider "aws" {
  region  = "ap-south-1"
  profile = "terraform"
}


variable "instance_names" {

  type = set(string)

  default = [
    "webserver",
    "appserver",
    "dbserver"
  ]
}


resource "aws_instance" "servers" {

  for_each = var.instance_names

  ami           = "ami-xxxxxxxxxxxxxxxxx"
  instance_type = "t2.micro"

  tags = {
    Name = each.value
  }
}
```

Terraform creates:

```text
webserver
appserver
dbserver
```

Terraform state addresses:

```text
aws_instance.servers["webserver"]
aws_instance.servers["appserver"]
aws_instance.servers["dbserver"]
```

# 6. Using a Map with `for_each`

This is where `for_each` becomes very useful.

Suppose we want:

```text
webserver → t2.micro
appserver → t2.small
dbserver  → t2.medium
```

Create a map:

```hcl
variable "instances" {

  default = {
    webserver = "t2.micro"
    appserver = "t2.small"
    dbserver  = "t2.medium"
  }
}
```

Then:

```hcl
resource "aws_instance" "servers" {

  for_each = var.instances

  ami = "ami-xxxxxxxxxxxxxxxxx"

  instance_type = each.value

  tags = {
    Name = each.key
  }
}
```

---

# 7. Understanding `each.key` and `each.value`

Our map:

```hcl
{
  webserver = "t2.micro"
  appserver = "t2.small"
  dbserver  = "t2.medium"
}
```

Terraform processes:

```text
each.key       each.value

webserver      t2.micro
appserver      t2.small
dbserver       t2.medium
```

Therefore:

```hcl
instance_type = each.value
```

means:

```text
webserver → t2.micro
appserver → t2.small
dbserver  → t2.medium
```

And:

```hcl
Name = each.key
```

means the EC2 Name tags become:

```text
webserver
appserver
dbserver
```

# 8. Complete EC2 Example Using Map

```hcl
provider "aws" {
  region  = "ap-south-1"

variable "instances" {

  type = map(string)

  default = {

    appserver = "t2.small"

    dbserver = "t2.medium"

  }
}


resource "aws_instance" "servers" {

  for_each = var.instances

  ami = "ami-xxxxxxxxxxxxxxxxx"

  instance_type = each.value

  tags = {
    Name        = each.key
    Environment = "Dev"
  }
}
```

Terraform will create:

```text
webserver
   ↓
t2.micro

appserver
   ↓
t2.small

dbserver
   ↓
t2.medium
```

# 9. Map of Objects — Real-Time Example

For more advanced configurations, each EC2 instance may need multiple values:

```text
Name
Instance Type
Environment
```

We can use a **map of objects**.

```hcl
variable "instances" {

  default = {

    webserver = {
      instance_type = "t2.micro"
      environment   = "Dev"
    }

    appserver = {
      instance_type = "t2.small"
      environment   = "Test"
    }

    dbserver = {
      instance_type = "t2.medium"
      environment   = "Prod"
    }

  }
}
```

Resource:

```hcl
resource "aws_instance" "servers" {

  for_each = var.instances

  ami = "ami-xxxxxxxxxxxxxxxxx"

  instance_type = each.value.instance_type

  tags = {
    Name        = each.key
    Environment = each.value.environment
  }
}
```

### Understanding it

For `webserver`:

```text
each.key

webserver
```

and:

```text
each.value.instance_type

t2.micro
```

and:

```text
each.value.environment

Dev
```

So Terraform creates:

```text
webserver
├── Instance Type: t2.micro
└── Environment: Dev


appserver
├── Instance Type: t2.small
└── Environment: Test


dbserver
├── Instance Type: t2.medium
└── Environment: Prod
```

# 10. Referencing a Resource Created with `for_each`

Suppose:

```hcl
resource "aws_instance" "servers" {

  for_each = var.instances

  ami           = "ami-xxxxxxxxxxxxxxxxx"
  instance_type = each.value

  tags = {
    Name = each.key
  }
}
```

To reference `webserver`:

```hcl
aws_instance.servers["webserver"].id
```

For `appserver`:

```hcl
aws_instance.servers["appserver"].id
```

For `dbserver`:

```hcl
aws_instance.servers["dbserver"].id
```

Example:

```hcl
output "webserver_id" {

  value = aws_instance.servers["webserver"].id
}
```

# 11. Output All EC2 Public IPs

Because `for_each` produces a map of resource instances, a `for` expression is a clear way to collect their IPs:

```hcl
output "public_ips" {

  value = {
    for name, server in aws_instance.servers :
    name => server.public_ip
  }
}
```

Example output:

```text
public_ips = {
  "appserver" = "13.x.x.x"
  "dbserver"  = "3.x.x.x"
  "webserver" = "15.x.x.x"
}
```

This is useful because we know **which IP belongs to which server**.

# 12. Why `for_each` Can Be Better Than `count`

Suppose we use `count`:

```text
[0] dev
[1] test
[2] prod
```

If we remove `test`, the indexes can shift:

```text
[0] dev
[1] prod
```

Terraform tracks these resources using indexes.

With `for_each`:

```text
["dev"]
["test"]
["prod"]
```

Remove:

```text
test
```

Remaining resources are still:

```text
["dev"]
["prod"]
```

Their keys don't change.

This is one of the main reasons `for_each` is useful when resources have **unique identities**.

---

# 13. `count` vs `for_each`

| Feature                     | `count`                 | `for_each`               |
| --------------------------- | ----------------------- | ------------------------ |
| Identification              | Numeric index           | Key                      |
| Example                     | `[0]`                   | `["web"]`                |
| Special value               | `count.index`           | `each.key`, `each.value` |
| Common collection           | List                    | Map / Set                |
| Identical resources         | Very convenient         | Supported                |
| Unique named resources      | Less convenient         | Very convenient          |
| Adding/removing middle item | Can cause index changes | Stable keys help         |

# 14. Same IAM Example: `count` vs `for_each`

### Using `count`

```hcl
variable "users" {

  default = [
    "dev",
    "test",
    "prod"
  ]
}


resource "aws_iam_user" "users" {

  count = length(var.users)

  name = var.users[count.index]
}
```

Terraform addresses:

```text
aws_iam_user.users[0]
aws_iam_user.users[1]
aws_iam_user.users[2]
```

---

### Using `for_each`

```hcl
variable "users" {

  default = [
    "dev",
    "test",
    "prod"
  ]
}


resource "aws_iam_user" "users" {

  for_each = toset(var.users)

  name = each.value
}
```

Terraform addresses:

```text
aws_iam_user.users["dev"]
aws_iam_user.users["test"]
aws_iam_user.users["prod"]
```

This makes the resource identity easier to understand.

# 17. Important Limitation

`for_each` cannot directly use a normal list like:

```hcl
for_each = [
  "dev",
  "test",
  "prod"
]
```

Instead, convert it to a set:

```hcl
for_each = toset([
  "dev",
  "test",
  "prod"
])
```

Or define the variable as:

```hcl
variable "users" {

  type = set(string)

  default = [
    "dev",
    "test",
    "prod"
  ]
}
```

Then:

```hcl
for_each = var.users
```

