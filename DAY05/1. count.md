# Terraform `count` Meta-Argument

## 1. What is `count` in Terraform?

`count` is a **Terraform meta-argument** used to create **multiple instances of the same resource** from a single resource block.

Instead of writing:

```hcl
resource "aws_instance" "server1" {
  # configuration
}

resource "aws_instance" "server2" {
  # configuration
}

resource "aws_instance" "server3" {
  # configuration
}
```

We can write one resource block:

```hcl
resource "aws_instance" "server" {
  count = 3

  # configuration
}
```

Terraform creates:

```text
aws_instance.server[0]
aws_instance.server[1]
aws_instance.server[2]
```

> `count` indexing starts from **0**.

---

# 2. Basic Syntax

```hcl
resource "resource_type" "resource_name" {

  count = NUMBER

  # Resource configuration
}
```

Example:

```hcl
count = 3
```

means:

```text
Create 3 instances of this resource
```

---

# 3. `count.index`

When `count` is used, Terraform provides:

```hcl
count.index
```

It represents the index number of the current resource.

For:

```hcl
count = 3
```

Terraform uses:

```text
First resource  → count.index = 0
Second resource → count.index = 1
Third resource  → count.index = 2
```

---

# Use Case 1: Create Multiple EC2 Instances

Suppose we need **3 EC2 instances**.

Without `count`, we would need three resource blocks.

With `count`:

```hcl
provider "aws" {
  region  = "ap-south-1"
  profile = "terraform"
}

resource "aws_instance" "webserver" {

  count = 3

  ami           = "ami-xxxxxxxxxxxxxxxxx"
  instance_type = "t2.micro"

  tags = {
    Name = "WebServer-${count.index}"
  }
}
```

Run:

```bash
terraform init
terraform fmt
terraform validate
terraform plan
terraform apply
```

Terraform creates:

```text
WebServer-0
WebServer-1
WebServer-2
```

Resource addresses:

```text
aws_instance.webserver[0]
aws_instance.webserver[1]
aws_instance.webserver[2]
```

---

# 4. Start EC2 Names from 1

Normally:

```hcl
Name = "WebServer-${count.index}"
```

produces:

```text
WebServer-0
WebServer-1
WebServer-2
```

If we want:

```text
WebServer-1
WebServer-2
WebServer-3
```

use:

```hcl
Name = "WebServer-${count.index + 1}"
```

Complete example:

```hcl
resource "aws_instance" "webserver" {

  count = 3

  ami           = "ami-xxxxxxxxxxxxxxxxx"
  instance_type = "t2.micro"

  tags = {
    Name = "WebServer-${count.index + 1}"
  }
}
```

# Use Case 2: Create Multiple IAM Users

We can also use `count` with IAM users.

Example:

```hcl
provider "aws" {
  region  = "ap-south-1"
  profile = "terraform"
}

resource "aws_iam_user" "users" {

  count = 3

  name = "developer-${count.index + 1}"
}
```

Terraform creates:

```text
developer-1
developer-2
developer-3
```

Terraform resource addresses:

```text
aws_iam_user.users[0]
aws_iam_user.users[1]
aws_iam_user.users[2]
```

# Use Case 3: IAM Users Using a List

Suppose we need these users:

```text
dev
test
prod
```

Create a variable:

```hcl
variable "iam_users" {

  default = [
    "dev",
    "test",
    "prod"
  ]
}
```

Then:

```hcl
resource "aws_iam_user" "users" {

  count = length(var.iam_users)

  name = var.iam_users[count.index]
}
```

### How does this work?

Our list is:

```hcl
[
  "dev",
  "test",
  "prod"
]
```

Indexes are:

```text
Index 0 → dev
Index 1 → test
Index 2 → prod
```

Terraform evaluates:

```text
count.index = 0
var.iam_users[0]
        ↓
       dev
```

Then:

```text
count.index = 1
var.iam_users[1]
        ↓
       test
```

Then:

```text
count.index = 2
var.iam_users[2]
        ↓
       prod
```

Final result:

```text
aws_iam_user.users[0] → dev
aws_iam_user.users[1] → test
aws_iam_user.users[2] → prod
```

# Use Case 7: Conditional Resource Creation

Another important use case of `count` is to decide whether a resource should be created.

Example:

```hcl
variable "create_ec2" {
  type    = bool
  default = true
}
```

Resource:

```hcl
resource "aws_instance" "webserver" {

  count = var.create_ec2 ? 1 : 0

  ami           = "ami-xxxxxxxxxxxxxxxxx"
  instance_type = "t2.micro"

  tags = {
    Name = "WebServer"
  }
}
```

If:

```hcl
create_ec2 = true
```

Terraform evaluates:

```text
true ? 1 : 0
       ↓
       1
```

One EC2 instance is created.

If:

```hcl
create_ec2 = false
```

Terraform evaluates:

```text
false ? 1 : 0
        ↓
        0
```

No EC2 instance is created.

This pattern is commonly used for **optional resources**.

# 8. Referencing a Resource Created with `count`

Suppose:

```hcl
resource "aws_instance" "webserver" {

  count = 3

  ami           = "ami-xxxxxxxxxxxxxxxxx"
  instance_type = "t2.micro"
}
```

To reference the first instance:

```hcl
aws_instance.webserver[0].id
```

Second:

```hcl
aws_instance.webserver[1].id
```

Third:

```hcl
aws_instance.webserver[2].id
```

For example:

```hcl
output "first_instance_id" {

  value = aws_instance.webserver[0].id
}
```

---

# 9. Output All EC2 Public IPs

Instead of selecting one instance, we can output information for all instances.

```hcl
output "public_ips" {

  value = aws_instance.webserver[*].public_ip
}
```

Example output:

```text
public_ips = [
  "13.x.x.x",
  "15.x.x.x",
  "3.x.x.x"
]
```

The `[*]` is used to obtain the attribute from all instances.

---

# 10. Complete EC2 Example

```hcl
provider "aws" {
  region  = "ap-south-1"
  profile = "terraform"
}


variable "instance_names" {

  default = [
    "webserver",
    "appserver",
    "dbserver"
  ]
}


resource "aws_instance" "servers" {

  count = length(var.instance_names)

  ami           = "ami-xxxxxxxxxxxxxxxxx"
  instance_type = "t2.micro"

  tags = {
    Name        = var.instance_names[count.index]
    Environment = "Dev"
  }
}


output "instance_ids" {

  value = aws_instance.servers[*].id
}


output "public_ips" {

  value = aws_instance.servers[*].public_ip
}
```

# 12. Important Point About `count`

`count` works very well when resources are essentially identical or when you're working with a simple ordered list.

However, Terraform identifies them by numerical index:

```text
resource[0]
resource[1]
resource[2]
```

This becomes important when changing lists.

For example:

```hcl
[
  "dev",
  "test",
  "prod"
]
```

If you remove:

```text
test
```

the indexes can change:

```text
Before:

[0] dev
[1] test
[2] prod

After:

[0] dev
[1] prod
```

Because the resource addresses are index-based, Terraform may propose changes you did not initially expect.

For resources with **unique names/keys** where items may frequently be added or removed, `for_each` is often a better fit.

---

# 13. `count` vs `for_each`

Simple difference:

| `count`                      | `for_each`                         |
| ---------------------------- | ---------------------------------- |
| Uses numeric indexes         | Uses keys                          |
| `count.index`                | `each.key`, `each.value`           |
| Good for identical resources | Good for uniquely named resources  |
| Works naturally with lists   | Works naturally with maps and sets |
| Address: `[0]`, `[1]`        | Address: `["dev"]`, `["prod"]`     |

Example:

```text
count

aws_iam_user.users[0]
aws_iam_user.users[1]
```

vs:

```text
for_each

aws_iam_user.users["dev"]
aws_iam_user.users["prod"]
```
