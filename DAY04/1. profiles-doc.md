# Terraform AWS Authentication Using IAM User & AWS CLI Profiles

## Objective

In this lab, we will understand:

```text
1. Create IAM User
2. Create Access Key and Secret Key
3. Configure AWS CLI Default Profile
4. Configure Multiple Named Profiles
5. List AWS Profiles
6. Check Profile Configuration
7. Validate Credentials
8. Use Access Key & Secret Key directly in Terraform
9. Use Default AWS Profile with Terraform
10. Use Named AWS Profile with Terraform
11. Create EC2 using Terraform
```

AWS CLI stores named profiles in its shared configuration/credentials files. When no profile is explicitly selected, the `default` profile is used. ([AWS Documentation][1])

---

# 1. Create IAM User in AWS

Login to:

**AWS Console → IAM → Users → Create user**

Example:

```text
User name: terraform-user
```

Click:

```text
Create user
```

For a simple classroom EC2 lab, attach permissions that allow the EC2 operations your Terraform configuration requires. Avoid broad administrator permissions in real environments; use least-privilege policies.

# 2. Create Access Key and Secret Key

Open:

```text
IAM
 ↓
Users
 ↓
terraform-user
 ↓
Security credentials
 ↓
Access keys
 ↓
Create access key
```

You will receive:

```text
Access Key ID
Secret Access Key
```

Example placeholders:

```text
Access Key ID:
AKIAxxxxxxxxxxxxxxxx

Secret Access Key:
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

> **Important:** Never upload real Access Keys or Secret Keys to GitHub.

# 4. Configure Default AWS Profile

Run:

```bash
aws configure
```

Enter:

```text
AWS Access Key ID [None]: <ACCESS-KEY>
AWS Secret Access Key [None]: <SECRET-KEY>
Default region name [None]: ap-south-1
Default output format [None]: json
```

This creates/configures the:

```text
default
```

profile.

AWS documents that `aws configure` writes the access key and secret key to the shared credentials file. ([AWS Documentation][2])

---

# 5. Check Default Profile

Run:

```bash
aws configure list
```

Example:

```text
NAME       VALUE                    TYPE
profile    <not set>                None
access_key ****************ABCD     shared-credentials-file
secret_key ****************XYZ1     shared-credentials-file
region     ap-south-1               config-file
```

This command is useful because it shows not only the configuration but also **where AWS CLI obtained each value**. ([AWS Documentation][3])

# 6. Validate AWS Credentials

A very useful validation command is:

```bash
aws sts get-caller-identity
```

Example:

```json
{
    "UserId": "AIDAXXXXXXXXXXXXXXXX",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/terraform-user"
}
```

This confirms:

```text
AWS CLI
   ↓
Credentials loaded
   ↓
Authentication successful
   ↓
AWS Account identified
```

You can also test EC2 access:

```bash
aws ec2 describe-instances
```

# 7. Configure a Named Profile

Suppose we don't want to use `default`.

We want a profile called:

```text
terraform
```

Run:

```bash
aws configure --profile terraform
```

Enter:

```text
AWS Access Key ID [None]: <ACCESS-KEY>
AWS Secret Access Key [None]: <SECRET-KEY>
Default region name [None]: ap-south-1
Default output format [None]: json
```

The `--profile` option creates or uses a named profile. ([AWS Documentation][1])

# 12. Where Are AWS Profiles Stored?

### Linux / macOS

```text
~/.aws/credentials
~/.aws/config
```

Check:

```bash
cat ~/.aws/credentials
```

```bash
cat ~/.aws/config
```

### Windows

Normally:

```text
C:\Users\<username>\.aws\credentials
C:\Users\<username>\.aws\config
```

For example:

```text
C:\Users\Prasanth\.aws\credentials
```

AWS uses separate shared credentials and configuration files for these settings. ([AWS Documentation][1])

---

# 13. Example Credentials File

The file:

```text
~/.aws/credentials
```

might contain:

```ini
[default]
aws_access_key_id = <ACCESS-KEY>
aws_secret_access_key = <SECRET-KEY>

[terraform]
aws_access_key_id = <ACCESS-KEY>
aws_secret_access_key = <SECRET-KEY>

[dev]
aws_access_key_id = <ACCESS-KEY>
aws_secret_access_key = <SECRET-KEY>
```

Never push this file to GitHub.

---

# 14. Example Config File

The file:

```text
~/.aws/config
```

might contain:

```ini
[default]
region = ap-south-1
output = json

[profile terraform]
region = ap-south-1
output = json

[profile dev]
region = ap-south-1
output = json
```

Notice the difference:

```text
credentials file:

[terraform]


config file:

[profile terraform]
```

This distinction is documented by AWS. ([AWS Documentation][1])

# Terraform Authentication

Now let's use these credentials with Terraform.

There are multiple approaches.

---

# Method 1: Pass Access Key and Secret Key Directly

## main.tf

```hcl
provider "aws" {

  region = "ap-south-1"

  access_key = "YOUR_ACCESS_KEY"

  secret_key = "YOUR_SECRET_KEY"
}


resource "aws_instance" "webserver" {

  ami = "ami-xxxxxxxxxxxxxxxxx"

  instance_type = "t2.micro"

  tags = {
    Name = "Terraform-EC2"
  }
}
```

Then:

```bash
terraform init
```

```bash
terraform validate
```

```bash
terraform plan
```

```bash
terraform apply
```

### Important

This method is useful to **understand how authentication works**, but it should **not be used in real projects**.

Do NOT do this:

```hcl
access_key = "AKIA123456..."
secret_key = "abcd123456..."
```

and then:

```bash
git add .
git commit -m "terraform code"
git push
```

Your AWS credentials could be exposed.

HashiCorp specifically recommends against putting credentials directly in the provider configuration. ([HashiCorp Developer][6])

---

# Method 2: Use Default AWS Profile

First:

```bash
aws configure
```

Validate:

```bash
aws sts get-caller-identity
```

Now Terraform code:

```hcl
provider "aws" {

  region = "ap-south-1"

}


resource "aws_instance" "webserver" {

  ami = "ami-xxxxxxxxxxxxxxxxx"

  instance_type = "t2.micro"

  tags = {
    Name = "Terraform-Default-Profile"
  }
}
```

Notice:

```text
NO access_key
NO secret_key
NO profile
```

Terraform's AWS provider can use AWS shared credentials/configuration mechanisms, so the default credentials can be discovered without putting secrets in `main.tf`. ([HashiCorp Developer][7])

Flow:

```text
Terraform
    ↓
AWS Provider
    ↓
Default AWS Credentials
    ↓
AWS
    ↓
Create EC2
```

---

# Method 3: Explicitly Mention Default Profile

We can also explicitly write:

```hcl
provider "aws" {

  region = "ap-south-1"

  profile = "default"

}


resource "aws_instance" "webserver" {

  ami = "ami-xxxxxxxxxxxxxxxxx"

  instance_type = "t2.micro"

  tags = {
    Name = "Terraform-Default-Profile"
  }
}
```

# Method 4: Use Named AWS Profile

Suppose we created:

```bash
aws configure --profile terraform
```

Validate:

```bash
aws sts get-caller-identity --profile terraform
```

Terraform:

```hcl
provider "aws" {

  region = "ap-south-1"

  profile = "terraform"

}


resource "aws_instance" "webserver" {

  ami = "ami-xxxxxxxxxxxxxxxxx"

  instance_type = "t2.micro"

  tags = {
    Name = "Terraform-Named-Profile"
  }
}
```

Now the flow is:

```text
Terraform
     ↓
AWS Provider
     ↓
profile = "terraform"
     ↓
AWS Shared Credentials
     ↓
[terraform]
     ↓
Access Key + Secret Key
     ↓
AWS API
     ↓
EC2 Instance
```

---

# Method 5: Change Profile Without Changing Terraform Code

Another useful method is using the `AWS_PROFILE` environment variable.

For Linux:

```bash
export AWS_PROFILE=terraform
```

Check:

```bash
echo $AWS_PROFILE
```

Then Terraform can remain:

```hcl
provider "aws" {
  region = "ap-south-1"
}
```

Run:

```bash
terraform plan
terraform apply
```

AWS CLI documents `AWS_PROFILE` as a way to select a named profile for subsequent commands instead of repeatedly supplying `--profile`. ([AWS Documentation][1])

# Important Commands Cheat Sheet

```bash
# Configure default profile
aws configure

# Configure named profile
aws configure --profile terraform

# List profiles
aws configure list-profiles

# Check default configuration
aws configure list

# Check named profile configuration
aws configure list --profile terraform

# Validate default credentials
aws sts get-caller-identity

# Validate named profile
aws sts get-caller-identity --profile terraform

# List EC2 using default profile
aws ec2 describe-instances

# List EC2 using named profile
aws ec2 describe-instances --profile terraform

# Set profile temporarily - Linux
export AWS_PROFILE=terraform

# Terraform
terraform init
terraform fmt
terraform validate
terraform plan
terraform apply
terraform destroy
```
