# Terraform `fmt` Command

## 1. What is `terraform fmt`?

`terraform fmt` stands for **Terraform Format**.

It automatically formats Terraform configuration files into the **standard and consistent style recommended by Terraform**.

```bash
terraform fmt
```

Think of it as:

```text
Unformatted Terraform Code
        ↓
terraform fmt
        ↓
Properly Formatted Terraform Code
```

---

## 2. Why Do We Use `terraform fmt`?

When multiple developers write Terraform code, everyone may use different spacing and indentation.

`terraform fmt` helps maintain:

* Consistent indentation
* Proper spacing
* Better readability
* Standard Terraform code style
* Cleaner code before committing to Git/GitHub

---

# 3. Example Before `terraform fmt`

Suppose `main.tf` contains:

```hcl
provider "aws" {
region="ap-south-1"
profile="terraform"
}

resource "aws_instance" "webserver" {
ami="ami-xxxxxxxxxxxxxxxxx"
instance_type="t2.micro"

tags={
Name="Terraform-WebServer"
Environment="Dev"
}
}
```

The code may work, but the formatting is poor.

Run:

```bash
terraform fmt
```

---

# 4. After `terraform fmt`

Terraform automatically changes the file to:

```hcl
provider "aws" {
  region  = "ap-south-1"
  profile = "terraform"
}

resource "aws_instance" "webserver" {
  ami           = "ami-xxxxxxxxxxxxxxxxx"
  instance_type = "t2.micro"

  tags = {
    Name        = "Terraform-WebServer"
    Environment = "Dev"
  }
}
```

Notice the changes:

```text
Proper indentation
Proper spacing
Aligned "=" symbols where appropriate
Consistent Terraform formatting
```

# 5. Basic Syntax

```bash
terraform fmt
```

Run this command from the directory containing your Terraform files.

Example:

```text
terraform-project/
│
├── main.tf
├── variables.tf
├── outputs.tf
└── provider.tf
```

Run:

```bash
cd terraform-project

terraform fmt
```

Terraform formats the `.tf` files in the current directory.

---

# 6. Example

Check files:

```bash
ls
```

Output:

```text
main.tf
variables.tf
outputs.tf
```

Run:

```bash
terraform fmt
```

You might see:

```text
main.tf
variables.tf
```

This means Terraform modified those files because formatting changes were required.

If you run:

```bash
terraform fmt
```

again and there is no output, it generally means there were no additional formatting changes to make.

---

# 7. Format Subdirectories

By default:

```bash
terraform fmt
```

works on the current directory.

If your Terraform project contains Terraform code inside subdirectories/modules, use:

```bash
terraform fmt -recursive
```

Example structure:

```text
terraform-project/
│
├── main.tf
│
├── variables.tf
│
└── modules/
    │
    ├── ec2/
    │   └── main.tf
    │
    └── vpc/
        └── main.tf
```

Run:

```bash
terraform fmt -recursive
```

Terraform will format Terraform files throughout the directory tree.

---

# 8. Check Formatting Without Modifying Files

Sometimes we only want to **check** whether files are formatted correctly.

Use:

```bash
terraform fmt -check
```

This is especially useful in:

```text
CI/CD pipelines
GitHub Actions
Jenkins
Code reviews
```

If formatting is incorrect, the command returns a non-zero exit status, making it useful as a pipeline quality check.

---

# 9. Show Formatting Differences

Use:

```bash
terraform fmt -diff
```

This displays the formatting differences.

Example:

```bash
terraform fmt -diff
```

Instead of only knowing that formatting changed, you can see what Terraform changed.

---

# 10. Check + Show Difference

You can combine options:

```bash
terraform fmt -check -diff
```

This is useful in CI/CD:

```text
Developer pushes Terraform code
             ↓
       CI/CD Pipeline
             ↓
terraform fmt -check -diff
             ↓
     Formatting correct?
        /          \
      YES           NO
       ↓             ↓
   Continue       Fail Check
```

---

# 11. Recursive Formatting Check

For larger projects:

```bash
terraform fmt -recursive
```

To check the whole project without changing files:

```bash
terraform fmt -check -recursive
```

---

# 12. Common `terraform fmt` Commands

| Command                           | Purpose                                     |
| --------------------------------- | ------------------------------------------- |
| `terraform fmt`                   | Format Terraform files                      |
| `terraform fmt -recursive`        | Format current directory and subdirectories |
| `terraform fmt -check`            | Check whether formatting is required        |
| `terraform fmt -diff`             | Display formatting differences              |
| `terraform fmt -check -diff`      | Check formatting and show differences       |
| `terraform fmt -check -recursive` | Check formatting recursively                |

# 13. `terraform fmt` vs `terraform validate`

These two commands serve different purposes.

### `terraform fmt`

Checks/fixes **formatting and style**.

```bash
terraform fmt
```

Example:

```hcl
instance_type="t2.micro"
```

becomes:

```hcl
instance_type = "t2.micro"
```

### `terraform validate`

Checks whether the Terraform configuration is **syntactically valid and internally consistent**.

```bash
terraform validate
```

So remember:

```text
terraform fmt
     ↓
Formatting / Style

terraform validate
     ↓
Configuration Validation
```

`terraform fmt` does **not** mean your infrastructure configuration is valid.

---

# 14. Recommended Terraform Workflow

A simple workflow is:

```bash
terraform init
```

Then:

```bash
terraform fmt
```

Then:

```bash
terraform validate
```

Then:

```bash
terraform plan
```

Finally:

```bash
terraform apply
```

Flow:

```text
Write Terraform Code
        ↓
terraform init
        ↓
terraform fmt
        ↓
terraform validate
        ↓
terraform plan
        ↓
terraform apply
        ↓
Infrastructure Created
```

---

# 15. Before Pushing Code to GitHub

A good practice is:

```bash
terraform fmt -recursive
terraform validate
terraform plan
```

Then:

```bash
git status
git add .
git commit -m "Added Terraform configuration"
git push
```

This helps keep Terraform code clean and consistent.
