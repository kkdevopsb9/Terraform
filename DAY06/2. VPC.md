# Terraform VPC Infrastructure Setup - Mumbai Region

## Scenario

Create a VPC in the Mumbai region `ap-south-1` with the following resources:

- 1 VPC
- 2 Availability Zones
  - ap-south-1a
  - ap-south-1b
- 4 Subnets
  - 2 Public Subnets
  - 2 Private Subnets
- 1 Internet Gateway
- 1 NAT Gateway
- Public Route Table
- Private Route Table

All the resources are configured in a single `main.tf` file.

## Terraform Code - main.tf

```hcl
provider "aws" {
  region = "ap-south-1"
}

# VPC
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"

  tags = {
    Name = "kkfunda-vpc"
  }
}

# Internet Gateway
resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.main.id

  tags = {
    Name = "kkfunda-igw"
  }
}

# Public Subnet 1
resource "aws_subnet" "public_subnet_1" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = "ap-south-1a"
  map_public_ip_on_launch = true

  tags = {
    Name = "kkfunda-public-1"
  }
}

# Public Subnet 2
resource "aws_subnet" "public_subnet_2" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.2.0/24"
  availability_zone       = "ap-south-1b"
  map_public_ip_on_launch = true

  tags = {
    Name = "kkfunda-public-2"
  }
}

# Private Subnet 1
resource "aws_subnet" "private_subnet_1" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.3.0/24"
  availability_zone = "ap-south-1a"

  tags = {
    Name = "kkfunda-private-1"
  }
}

# Private Subnet 2
resource "aws_subnet" "private_subnet_2" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.4.0/24"
  availability_zone = "ap-south-1b"

  tags = {
    Name = "kkfunda-private-2"
  }
}

# Elastic IP for NAT Gateway
resource "aws_eip" "nat_eip" {
  domain = "vpc"
}

# NAT Gateway
resource "aws_nat_gateway" "nat_gw" {
  allocation_id = aws_eip.nat_eip.id
  subnet_id     = aws_subnet.public_subnet_1.id

  tags = {
    Name = "kkfunda-nat"
  }

  depends_on = [aws_internet_gateway.igw]
}

# Public Route Table
resource "aws_route_table" "public_rt" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }

  tags = {
    Name = "kkfunda-public-rt"
  }
}

# Associate Public Subnet 1 with Public Route Table
resource "aws_route_table_association" "public_assoc_1" {
  subnet_id      = aws_subnet.public_subnet_1.id
  route_table_id = aws_route_table.public_rt.id
}

# Associate Public Subnet 2 with Public Route Table
resource "aws_route_table_association" "public_assoc_2" {
  subnet_id      = aws_subnet.public_subnet_2.id
  route_table_id = aws_route_table.public_rt.id
}

# Private Route Table
resource "aws_route_table" "private_rt" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block     = "0.0.0.0/0"
    nat_gateway_id = aws_nat_gateway.nat_gw.id
  }

  tags = {
    Name = "kkfunda-private-rt"
  }
}

# Associate Private Subnet 1 with Private Route Table
resource "aws_route_table_association" "private_assoc_1" {
  subnet_id      = aws_subnet.private_subnet_1.id
  route_table_id = aws_route_table.private_rt.id
}

# Associate Private Subnet 2 with Private Route Table
resource "aws_route_table_association" "private_assoc_2" {
  subnet_id      = aws_subnet.private_subnet_2.id
  route_table_id = aws_route_table.private_rt.id
}
```

## Architecture Explanation

### VPC

The VPC is the main network boundary where all AWS networking resources are created.

CIDR block:

```text
10.0.0.0/16
```

This provides a large private IP address range for the resources inside the VPC.

### Public Subnets

Two public subnets are created in different Availability Zones.

```text
10.0.1.0/24 - ap-south-1a

10.0.2.0/24 - ap-south-1b
```

The following setting is enabled:

```hcl
map_public_ip_on_launch = true
```

This allows EC2 instances launched in these subnets to automatically receive a public IP address.

### Private Subnets

Two private subnets are created.

```text
10.0.3.0/24 - ap-south-1a

10.0.4.0/24 - ap-south-1b
```

Resources in private subnets do not receive direct internet access through the Internet Gateway.

### Internet Gateway

The Internet Gateway is attached to the VPC.

It is used by resources in public subnets to communicate with the internet.

The public route table contains:

```text
0.0.0.0/0 -> Internet Gateway
```

### NAT Gateway

The NAT Gateway is created inside the first public subnet.

```text
Public Subnet 1
10.0.1.0/24
```

The NAT Gateway requires an Elastic IP address.

Private subnet resources can use the NAT Gateway to access the internet for activities such as:

- Installing packages
- Downloading application dependencies
- Updating operating system packages
- Accessing external repositories

The internet cannot directly initiate connections to resources inside the private subnet through the NAT Gateway.

### Route Tables

The public route table contains:

```text
Destination: 0.0.0.0/0
Target: Internet Gateway
```

Both public subnets are associated with this route table.

The private route table contains:

```text
Destination: 0.0.0.0/0
Target: NAT Gateway
```

Both private subnets are associated with this route table.

## Network Flow

Public subnet traffic:

```text
EC2
 |
Public Subnet
 |
Public Route Table
 |
Internet Gateway
 |
Internet
```

Private subnet outbound traffic:

```text
EC2
 |
Private Subnet
 |
Private Route Table
 |
NAT Gateway
 |
Internet Gateway
 |
Internet
```

## Resource Summary

| Resource | Quantity | Purpose |
|---|---:|---|
| VPC | 1 | Main networking environment |
| Public Subnets | 2 | Resources requiring public connectivity |
| Private Subnets | 2 | Internal application or database resources |
| Internet Gateway | 1 | Internet connectivity for public subnets |
| Elastic IP | 1 | Public IP used by the NAT Gateway |
| NAT Gateway | 1 | Outbound internet access for private subnets |
| Public Route Table | 1 | Routes public traffic through the Internet Gateway |
| Private Route Table | 1 | Routes private outbound traffic through the NAT Gateway |

## Terraform Commands

Initialize Terraform:

```bash
terraform init
```

Validate the configuration:

```bash
terraform validate
```

Format the Terraform files:

```bash
terraform fmt
```

Check the execution plan:

```bash
terraform plan
```

Create the infrastructure:

```bash
terraform apply
```

Confirm with:

```text
yes
```

Check the created resources:

```bash
terraform state list
```

To delete all the resources created by Terraform:

```bash
terraform destroy
```

Confirm with:

```text
yes
```

## Important Note

A NAT Gateway is a chargeable AWS resource.

After completing practice or testing, destroy the infrastructure if it is no longer required.

```bash
terraform destroy
```
