# Terraform EC2 Internet Access Scenarios - Public and Private Subnets

This document explains how to launch EC2 instances in public and private subnets using Terraform and how internet access works in each case.

## Situation 1: EC2 in Public Subnet

### Scenario

Launch an EC2 instance inside the public subnet `aws_subnet.public_subnet_1`.

The instance should have:

- Public IP address
- Security group allowing SSH
- Outbound internet access
- Public subnet associated with an Internet Gateway

## Terraform Code

```hcl
# Security Group

resource "aws_security_group" "web_sg" {
  name        = "web-sg"
  description = "Allow SSH and outbound internet access"
  vpc_id      = aws_vpc.main.id

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name = "kkfunda-web-sg"
  }
}

# EC2 Instance in Public Subnet

resource "aws_instance" "public_ec2" {
  ami                         = "ami-03a54d2235b76d9d0"
  instance_type               = "t2.micro"
  subnet_id                   = aws_subnet.public_subnet_1.id
  key_name                    = "your-key-name"
  associate_public_ip_address = true
  vpc_security_group_ids      = [aws_security_group.web_sg.id]

  tags = {
    Name = "kkfunda-public-ec2"
  }
}
```

## How Public EC2 Gets Internet Access

The instance can access the internet because:

- It is launched inside a public subnet.
- It has a public IP address.
- The subnet is associated with a route table containing a route to the Internet Gateway.
- The security group allows outbound traffic.

The public route table should contain:

```text
Destination: 0.0.0.0/0
Target: Internet Gateway
```

Traffic flow:

```text
EC2 Instance
     |
Public Subnet
     |
Public Route Table
     |
Internet Gateway
     |
Internet
```

## Test Public EC2

Connect using SSH:

```bash
ssh -i your-key.pem ec2-user@<PUBLIC-IP>
```

Test internet connectivity:

```bash
curl https://google.com
```

You can also test DNS connectivity:

```bash
ping google.com
```

Note that some internet hosts may block ICMP ping, so `curl` is often a better internet connectivity test.

# Situation 2: EC2 in Private Subnet

## Scenario

Launch an EC2 instance inside the private subnet `aws_subnet.private_subnet_1`.

The instance should:

- Not have a public IP
- Use the same security group
- Use the private route table
- Access the internet through the NAT Gateway

## Terraform Code

```hcl
resource "aws_instance" "private_ec2" {
  ami                         = "ami-03a54d2235b76d9d0"
  instance_type               = "t2.micro"
  subnet_id                   = aws_subnet.private_subnet_1.id
  key_name                    = "your-key-name"
  associate_public_ip_address = false
  vpc_security_group_ids      = [aws_security_group.web_sg.id]

  tags = {
    Name = "kkfunda-private-ec2"
  }
}
```

## Private EC2 Internet Access

The private EC2 instance does not have direct internet connectivity through the Internet Gateway.

The instance has:

```text
Public IP: No
```

It cannot communicate directly with the Internet Gateway.

However, if the private route table contains a route to a NAT Gateway, the instance can access the internet for outbound traffic.

Private route table:

```text
Destination: 0.0.0.0/0
Target: NAT Gateway
```

Traffic flow:

```text
Private EC2
     |
Private Subnet
     |
Private Route Table
     |
NAT Gateway
     |
Public Subnet
     |
Internet Gateway
     |
Internet
```

This allows operations such as:

```bash
sudo yum update -y
```

```bash
sudo dnf update -y
```

```bash
curl https://google.com
```

The private instance can initiate connections to the internet, but users on the internet cannot directly initiate a connection to the private instance through the NAT Gateway.

# Public EC2 vs Private EC2

| Feature | Public EC2 | Private EC2 |
|---|---|---|
| Subnet | Public | Private |
| Public IP | Yes | No |
| Internet Gateway | Used directly | Not used directly |
| NAT Gateway | Not required | Required for outbound internet |
| Outbound Internet | Yes | Yes, through NAT |
| Direct SSH from Laptop | Yes | No |
| Suitable for | Public-facing services, bastion host | Backend, application, database servers |

# Connecting to Public EC2

From your local machine:

```bash
ssh -i your-key.pem ec2-user@<PUBLIC-IP>
```

Example:

```bash
ssh -i kkdevops.pem ec2-user@13.201.10.20
```

---

# Connecting to Private EC2

A private EC2 instance does not have a public IP, so direct SSH from the internet is not possible.

One common method is to use a bastion host.

Architecture:

```text
Laptop
   |
Internet
   |
Public EC2 / Bastion Host
   |
Private IP
   |
Private EC2
```

First connect to the public EC2 instance:

```bash
ssh -i your-key.pem ec2-user@<PUBLIC-EC2-IP>
```

Then connect from the public EC2 instance to the private EC2 instance:

```bash
ssh ec2-user@<PRIVATE-IP>
```

If the private key is required on the bastion host, it must be handled securely. In production environments, avoid unnecessarily copying private keys to servers.

AWS Systems Manager Session Manager is another secure option for accessing private EC2 instances without exposing SSH to the internet.

---

# Security Group Considerations

For the public instance, SSH can technically be allowed using:

```hcl
cidr_blocks = ["0.0.0.0/0"]
```

However, this allows SSH attempts from anywhere on the internet.

A better approach is to allow only your IP address:

```hcl
cidr_blocks = ["YOUR-PUBLIC-IP/32"]
```

For example:

```hcl
cidr_blocks = ["49.207.10.25/32"]
```

For the private EC2 instance, SSH can be restricted to traffic coming from the bastion host security group rather than allowing all IP addresses.

Example:

```hcl
resource "aws_security_group_rule" "private_ssh" {
  type                     = "ingress"
  from_port                = 22
  to_port                  = 22
  protocol                 = "tcp"
  security_group_id        = aws_security_group.private_sg.id
  source_security_group_id = aws_security_group.web_sg.id
}
```

# Important Points

A subnet is considered public when its route table has a route to an Internet Gateway.

Example:

```text
0.0.0.0/0 -> Internet Gateway
```

An EC2 instance also normally requires a public IPv4 address to communicate directly with the internet through the Internet Gateway.

A private subnet normally uses:

```text
0.0.0.0/0 -> NAT Gateway
```

The NAT Gateway is placed inside a public subnet.

A NAT Gateway provides outbound internet access for resources in private subnets.

It does not provide direct inbound internet connectivity to private EC2 instances.
